# Итоговый отчёт по доработке электронного журнала

Дата подготовки: 31 июля 2026 года.

## Реализованные задачи

1. Названия мессенджеров на странице восстановления пароля стали кликабельными. В контакте администратора добавлено отдельное поле имени пользователя; для Telegram используется имя пользователя, для поддерживаемых мессенджеров без имени — номер телефона.
2. «Партии оркестра» добавлены в блок «Справочники» административной панели.
3. Создан единый справочник «Произведения / элементы». В группе произведений значение выбирается только из связанного справочника соответствующего предмета; уже занятые в той же группе элементы не предлагаются повторно.
4. В карточке предмета название группы произведений выбирается раскрывающимся списком, сформированным из существующих записей таблицы «Группы произведений».
5. Все таблицы личного кабинета и административной панели получают двухосевую прокрутку на мобильных устройствах. Поддерживаются динамические административные formset-таблицы, сенсорное управление и клавиатурный фокус.
6. Во вкладке предмета «Группы, где есть этот предмет» добавлены полные стандартные действия Django Admin: создать, открыть, изменить и удалить учебную группу, а также отдельно добавить или удалить связь группы с предметом.
7. Демонстрационные данные разделены на архивный 2024/2025 и активный 2025/2026 учебные годы. Основные наборы учеников не повторяются и ограничены тремя учениками на группу; оценки, итоги и сдача произведений формируются для обоих лет.
8. Добавлены отдельные адаптивные правила для телефона в портретной и альбомной ориентациях, затем для планшета в обеих ориентациях. ПК-интерфейс не изменяется этими media queries.
9. В development и test используется `DummyCache`; Redis-кэш включается только при `DJANGO_ENV=production` или `prod`.
10. В production добавлены Redis, ограничение памяти с LRU-вытеснением, повторное использование соединений PostgreSQL и составные индексы под частые запросы журнала.
11. Excel-выгрузка дополнена каталогом произведений, партиями оркестра, квалификациями преподавателей, доступами к учебному году, настройками регистрации, контактами восстановления и расширенными данными сдачи произведений.
12. Инструкция администратора и документация запуска обновлены под новый порядок работы.
13. Для изменённых областей добавлен отдельный профильный сценарий `scripts/test-profile.sh`.
14. Каждая функциональная задача оформлена отдельным Git-коммитом; замечания итогового аудита вынесены в отдельный исправляющий коммит.

## Профильная проверка

Подготовлена команда:

```bash
./scripts/test-profile.sh
```

Она запускает только классы, относящиеся к изменённым областям:

- `AdminDashboardTests`;
- `PasswordRecoveryViewTests`;
- `CacheConfigurationTests`;
- `PerformanceConfigurationTests`;
- `SeedDataCommandTests`;
- `ElementAssessmentWorkflowTests`;
- `SelectedAcademicYearExportTests`.

В текущем рабочем окружении runtime-запуск остановился до загрузки проекта, поскольку пакет Django не установлен:

```text
ModuleNotFoundError: No module named 'django'
```

Поэтому в этом отчёте нет неподтверждённого утверждения об успешном прохождении Django-тестов. После установки зависимостей проверку нужно выполнить одной из команд:

```bash
python -m pip install -r requirements.txt
./scripts/test-profile.sh
```

или внутри development-контейнера:

```bash
docker compose --env-file .env.dev -f docker-compose.yml -f docker-compose.dev.yml exec web ./scripts/test-profile.sh
```

## Исправления, найденные итоговым аудитом

- исключено повторное создание настроек регистрации, которые уже создаются сигналом учебного года;
- подтверждённые заявки активного года возвращены в генерацию оценок и итогов;
- из выбора произведения исключены элементы, уже добавленные в ту же группу;
- профильная метка `slow/seed` возвращена классу seed-тестов;
- тест перемещения произведения обновлён под справочную модель;
- исключено повторное создание участия преподавателя в учебном году в Excel-тесте;
- проверка компактности наборов отделена от учеников, созданных подтверждёнными заявками.
