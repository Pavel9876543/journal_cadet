# Отчёт по исправлению админ-вкладок и тестовых данных

Дата проверки: 1 августа 2026 года.

## Реализовано

1. В карточке предмета вкладка «Группы, где есть этот предмет» содержит одну рабочую inline-форму и пустую строку для ручного добавления связи с существующей группой.
2. Повторный вывод inline-formset удалён из общего шаблона Django Admin. Из-за него отображались дублирующиеся кнопки и две management-form, а новые строки могли не сохраняться.
3. При ручном добавлении связи предмет автоматически передаётся новой inline-форме. Для группы доступны стандартные действия создания, просмотра, редактирования и удаления.
4. В форме ученика пустой вариант справочного инструмента называется «Другой инструмент». При его выборе доступно поле собственного инструмента. Поле партии доступно только для справочного инструмента, у которого существуют активные партии.
5. ФИО ученика и преподавателя обрабатывается в формате «Фамилия Имя Отчество». Логин создаётся как «Фамилия Имя», а поля Django User заполняются как `first_name=Имя`, `last_name=Фамилия`.
6. Поле контакта восстановления переименовано в «Имя пользователя в Telegram». Telegram использует username при наличии и телефон как запасной вариант; WhatsApp, Viber и остальные мессенджеры используют только телефон.
7. Добавлена миграция `0031_password_recovery_telegram_username_label`.
8. Seed-команда создаёт два соседних непересекающихся периода по 14 календарных дней. Одни и те же 15 основных учеников имеют зачисления в обоих периодах.
9. Тестовые ученики содержат данные партий оркестра, а одна подтверждённая заявка проверяет собственный инструмент «Гусли».
10. Copyright в Jazzmin формируется из текущего системного года.
11. Добавлены интеграционные тесты ручного сохранения связи предмета с группой, единственного inline-formset, зависимостей инструментов и партий, генерации логинов, Telegram-ссылок, Excel-заголовка, двухнедельных периодов и повторного зачисления тех же учеников.

- `python -m compileall -q config journal`;
- `node --check` для всех JavaScript-файлов в `journal/static`;
- синтаксическая проверка shell-скриптов из `scripts/` и `docker/`;
- проверка `.env.prod.example`, `.env.test` и совпадения `.env.test.example`;
- проверка зависимости миграции `0031` от `0030`;
- проверка единственного вывода inline-formset в шаблоне карточки админки;
- проверка ключевых инвариантов seed-команды;
- `git diff --check`.

Полный набор был запущен командой:

```bash
DJANGO_ENV=test DJANGO_ENV_FILE=.env.test python manage.py test -v 2
```

В текущем контейнере выполнение остановилось до обнаружения тестов с `ModuleNotFoundError: No module named 'django'`. Установка `requirements-dev.txt` также невозможна в этой среде: внутренний индекс пакетов не вернул `Django==5.2.16`, прямой сетевой доступ и Docker отсутствуют. Поэтому заявлять об успешном прохождении Django-тестов локально нельзя.

GitHub Actions по-прежнему устанавливает `requirements-dev.txt`, запускает lint, проверку миграций, `manage.py check`, быстрые и медленные Django-тесты и Docker smoke-test. Production deploy зависит от успешного обязательного CI-job.
