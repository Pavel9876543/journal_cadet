# Отчёт по обработке и журналированию ошибок

Дата: 2026-08-01

## Реализовано

1. В блоке «Связанные данные → Итоги по предметам» каждая запись теперь показывает:
   - оценку за экзамен;
   - итоговую оценку.
2. Добавлены безопасные и понятные страницы ошибок для HTTP-статусов 400, 401, 403, 404, 405, 408, 409, 413, 415, 422, 429, 500, 502, 503 и 504.
3. Для JSON/AJAX-запросов ошибки возвращаются в единой структуре с кодом, статусом, сообщением, рекомендациями и `request_id`.
4. Каждый запрос получает заголовок `X-Request-ID`; этот же код показывается пользователю и сохраняется в журнале ошибок.
5. Добавлена таблица «Журнал ошибок» в Django Admin. Она хранит:
   - дату и уровень;
   - HTTP-статус;
   - код ошибки;
   - путь и метод запроса;
   - пользователя;
   - источник, сообщение и traceback.
6. Хранилище автоматически оставляет не более 1000 последних ошибок. При добавлении новой записи старые удаляются.
7. В production журналирование в БД включено по умолчанию. В development и test оно отключено, чтобы не засорять локальную БД, при этом консольное логирование сохраняется.
8. Добавлена миграция `0032_errorlog`.
9. Обновлены env-примеры, генератор production env, валидатор env, README и инструкция администратора.

## Проверки

Успешно выполнены:

- компиляция всех Python-файлов через `compileall`;
- проверка `.env.test`, `.env.test.example` и `.env.prod.example`;
- синтаксическая проверка shell-скриптов через `bash -n`;
- проверка JavaScript-файлов через `node --check`;
- `git diff --check`;
- проверка ветки `main` и чистоты рабочего дерева после коммитов.

Полный запуск `python manage.py test --settings=config.test_settings` был инициирован, но остановился до обнаружения тестов: в доступном окружении отсутствует Django. Установка `requirements-dev.txt` также не удалась, потому что внутренний индекс пакетов не вернул `Django==5.2.16`, а публичный PyPI недоступен по DNS. Тесты добавлены в общий Django-набор и будут выполнены обязательным GitHub CI.
